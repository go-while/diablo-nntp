- didump: a read error in the middle of a dump no longer ends the dump as complete. didump printed "Error reading file" but still wrote the closing "." line and exited 0. After a read error (and when it cannot allocate its read buffer) the "." line is left out and didump exits 1; with `-f` a read error now ends the run the same way instead of retrying every 100 ms for ever (waiting at the end of the file is unchanged) (D-287). Note: diload accepts a dump without the final "." by design, so a `didump | diload` pipeline must check didump's own exit status: in sh use `set -o pipefail`. The old csh sample `samples/adm/old.biweekly.atrim.dexpire` checks only diload's `$status`, so it does not see this failure.
