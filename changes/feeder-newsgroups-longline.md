- `diablo`: a `Newsgroups:` header line longer than the input buffer (one page with the default `feederbuffersize`, about 4 KB, so a list of about 100 or more names) is read whole, also when it is a continuation line of a folded `Newsgroups:` header, up to the 16383-byte limit of the list; the name that limit cuts is left out, and so is everything after it. Before, only the first piece of such a line was read: the groups after it were missing from the active and moderation checks, `Xref:`, feed matching, the incoming filter and spool choice (with `activedrop yes` an article whose only carried group came after the first piece was refused NotInActive). Of the `Newsgroups:` line itself the first piece was read less its last byte, so its last name was looked up cut short and could name another group (with `feederautoaddtoactive on` the cut name was added to the active file as a new group); of a continuation line the name at the end of the first piece was left out. The received header lines are stored unchanged (only the generated `Xref:` line now lists the later groups). Tests: `TestNewsgroupsLongLine`, `TestNewsgroupsLongLineAutoAdd`, `TestNewsgroupsLongLineLimit`, `TestNewsgroupsFoldedLongLine` (D-209).
