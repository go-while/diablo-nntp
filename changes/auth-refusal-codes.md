- dreaderd: a backend refusal ("110 NNN text") goes to the client with its code only when the code is one a refusal can have, compared as the whole number: 400 and 502, and 481 after AUTHINFO. Any other code becomes 502 with the backend's text kept, so "110 281 Fine" no longer reaches the client as a success code on a refused connection. The "500" of the old "600 <minutes> 500 <text>" ban example goes out as 502.
- dreaderd: a client whose login is refused no longer gets the "180 ... status:" line when the readerdef taken for it (DEFAULT, for a failed AUTHINFO) has "status yes"; it gets its refusal (481 or 502). The same holds for a client with no access entry: with DEFAULT "status yes" it got 180 before, now "502 ... Access denied to your node". A monitoring host with its own access entry and a status readerdef still gets the status line.
