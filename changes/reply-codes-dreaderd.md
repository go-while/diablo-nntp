- dreaderd: reply codes from its backends must be the whole three-digit code the command defines, nothing in front or behind it, and an unknown code is an error: greeting, MODE READER, MODE READONLY, AUTHINFO USER (381, or 281 for a login without a password, which ended the connection before) and PASS (281), IHAVE (335), the end of a post (235), WHEREIS, ARTICLE, HEAD. An auth backend (Perl, NetRemote, file, cdb, db, radius, PAM) logs a user in only with "100 ..." or "110 <readerdef>"; before, any answer that started with 1 did ("199 no", "1garbage").
- dreaderd: a spool server reply to ARTICLE/HEAD that is neither the expected code nor a one-line refusal (a malformed status line, or a code with a text block after it) now closes the connection to that spool server after the client gets its refusal, so the left-over lines are not read as the next reply.
