- dreaderd: a header value with a NUL byte in it is now freed in full. The header copies made by lib/zalloc.c zallocStrTrim2() and zallocStrTrim() did not stop at a NUL byte, so the copy and its allocation went on past the end of the C string; the callers use the copy as a C string and free a length of strlen() + 1, so the bytes after the NUL stayed in the connection's memory until it closed. On a feed connection this happened for Newsgroups:, Message-ID:, Subject:, Date:, Xref: (xref slave mode), Control: and Supersedes:, and for From:, Sender: and Newsgroups: of a control message or superseding article (and the moderator and description lines of a newgroup body); on a reader connection for the Newsgroups:, Path: and Distribution: lines of a post (and Supersedes: and cancel targets with the POST_RESTRICTCANCEL build option; the From: copy of the POST_CKADDRESS build option is still shortened in place by HeaderCleanFrom() before it is freed, a separate follow-up). The memory grew with every such article or post, without limit. The copies now end at the first NUL; that is the value the code saw before as well, so replies, overview data and stored articles do not change.
