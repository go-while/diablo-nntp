- Configuration files (diablo.config, dspool.ctl, dexpire.ctl): a comment that starts after more than 255 characters of white space no longer makes the line "too long".
- dreaderd: readerdef numbers (`maxconn*`, `ratelimittax`, `bytelimit`, `pathcomponents`, `idletimeout`, `sessiontimeout`) must be whole non-negative numbers that fit an int; otherwise the error is logged and dreader.access is not installed (as for any invalid line). `dserver.hosts` `cachemin`, `cachemax`, `cacheabletime` and `retention` need a whole number (a bad one is logged and ignored); out-of-range numbers after the `p`, `s`, `o`, `t`, `T` flags are logged and ignored. The access-cache loader accepts file descriptor 0 and closes what it opened on failure.
- A malformed readerdef number means dreader.access is not installed. On a first start with no older access cache that means dreaderd refuses every client and keeps running (better than silently running with a default limit); the log line says so. A number of 40 or more characters is a bad value, not a cut one.
- dreaderd no longer crashes on a first start when dreader.access is refused and no access cache was ever installed. The access map is then empty, and SetAuthDetails() dereferenced a NULL reader definition (and, under `-d`, a NULL group/auth/vserver name) on the first client. The client is now refused (502) and the daemon keeps serving; the empty map denies like an unknown client.
- A refused dreader.access is logged once, not again on every main-loop pass (<=10 s) and every new connection. InstallAccessCache() kept the refused file's mtime/size/ino and skips it silently until it changes; a changed file is parsed again, and transient failures (open, lock) still retry.
