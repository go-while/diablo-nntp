- `dreaderd`: dreader.access typos no longer change what a readerdef does silently (D-164, D-166), and a missing access cache file no longer stops dreaderd (D-165):
  - **D-164:** a readerdef whose `groups`, `listgroups` or `postgroups` names a group list that no groupdef defines makes the file invalid ("readerdef X (line N): groups Y is not a groupdef"). It is not installed, as for a bad number (D-161). Before, the first group list, usually everything, was used for it at login. A readerdef without the setting (DEFAULT) still gets the first list.
  - **D-166:** a misspelled readerdef option makes the file invalid ("Invalid readerdef option ... the file is not installed"). Before, it was logged and the rest installed. `xzver` fell through to that message after it was set; it is accepted now. `settos` on a system without IP_TOS is logged as ignored, not refused.
  - The same for a misspelled option in a vserverdef, groupdef or authdef: the file is not installed.
  - **D-165:** when one of the five access cache files cannot be opened while the main process reloads them, it logs that and keeps the access map it has (or, with none, refuses that client), and tries again on the next connection. Before, the main dreaderd process exited.
  - Upgrade note: a dreader.access that has a misspelled option (in any definition) or group list name was installed before and is refused now. Check the log after upgrading. On a first start without an older access cache dreaderd then gives no service until the file is fixed.
