- dreaderd: the main process caches the reverse and forward lookup results per client address (`readerdnscachettl` 300 s, `readerdnscachenegttl` 60 s, `readerdnscachesize` 16384; a TTL of 0 turns it off). A client that reconnects within the TTL costs no lookup; access rules, auth and accounting still run on every login. Only definite answers are cached; with every libc except glibc and illumos/Solaris an address without a reverse name is never cached, because getnameinfo there cannot tell "no name" from a timeout.
- dreaderd: AUTHINFO reuses the lookup result of its connection, so an authenticated login does 2 lookups instead of 4, with or without the cache. A lookup that failed temporarily is done again.
- dreaderd: without netremote, a session end no longer sends an accounting request through a DNS worker. The `Connect=` count of `drcmd status` (and `connect=` of the status reply) no longer includes these requests.
- drcmd: `dnscache` prints the cache counters, `dnscache flush` empties it.
