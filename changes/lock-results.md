- Blocking file locks (`xflock`, `hflock`) start the wait again when a signal interrupts it. dexpireover's alarm()-timed waits still give up after `LockWaitTime`.
- Every blocking lock result is now checked. A failed lock is logged with the file and the error, and the site takes a safe path: skip the update, refuse the request (400 for a reader feed), or exit nonzero for a tool. A failed kpdb record or append lock is fatal, like a failed kpdb write, because going on could hand out an article number twice.
- A read-only history user (dilookup, dreadart, didump -f) that finds the history being created now waits for the creator. It used to ask for an exclusive lock on its read-only descriptor, which always failed, and then exited with "Unable to create ... read-only mode".
- doutq checks with F_GETLK whether a dnewslink works on a queue file, as OUTQ does. It no longer takes the lock itself, which made a dnewslink starting on the file skip it, and it works on queue files the user can only read.
