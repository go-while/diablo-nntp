- Every blocking file lock result is now checked. A failed lock is logged with the file and the error, and the site takes a safe path: skip the update, refuse the request (400 for a reader feed), or exit nonzero for a tool. A kpdb lock taken to change a record (article numbers) is tried a few more times on ENOLCK, then the process stops, as on a failed kpdb write. dreaderd commands that only read a group's record (GROUP, XOVER, posting checks) go on unlocked.
- Blocking locks start the wait again after EINTR. On Linux the kernel already restarts them under the SA_RESTART handlers Diablo uses. The retry matters where it does not, such as dreaderd's signal() on illumos. dexpireover's alarm()-timed waits still give up after `LockWaitTime`.
- A read-only history user (dilookup, dreadart, didump -f) that finds the history being created now waits for the creator. It used to exit with "Unable to create ... read-only mode". A fast-mode creator (diload -f, dhisexpire) keeps its lock throughout, so such a reader cannot make it fail.
- doutq checks with F_GETLK whether a dnewslink works on a queue file, as OUTQ does. It no longer takes the lock itself, which made a dnewslink starting on the file skip it, and it works on queue files the user can only read.
