- `dreaderd`: with a `cryptpw`, Injection-Info's `posting-host` (`rfc5537 yes`) is now encrypted as X-Trace and `posting-account` are, `C=<base64>` (`G=gen,C=...` with a generation), so the admin can read the client's name and address back from the header with the cryptpw, without a log. Before, it was an hourly hash (`de72e8eb.<clustername>`) that could not be read back. Without the encryption built in (`POST_CRYPTXTRACE` off) the hash stays. A new vserverdef option `showposthost no` leaves `posting-host` out (RFC 5536 3.2.8: every parameter is optional; INN's `addinjectionpostinghost`); the default is `yes`. NNTP-Posting-Host without `rfc5537` is unchanged.
- `contrib/xtrace/decrypt-aes.sh`: rewritten for plain sh (it needed bash and GNU sed). It reads an article or header on stdin and decrypts X-Trace and Injection-Info's `posting-host` and `posting-account`; it now passes `-md sha256 -A` to openssl, without which values over 64 base64 characters failed. The password can come as `pass:`, `env:` or `file:`.
