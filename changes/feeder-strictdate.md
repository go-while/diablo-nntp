- The feeder now applies Date time zones and checks article age with 64-bit arithmetic. Previously parsed zones were ignored; correctly applying them can change age-limit decisions. Two-digit years use the RFC 5322 window. A date without a zone uses server-local time; a date without a time uses local midnight; unknown named zones are treated as UTC. A numeric offset following a named zone takes precedence, as in INN, even when they disagree. `parsedate()` is also used by `didate` and the reader's article-age log, so those callers see the new RFC-style parsing too.
- With a positive `feedermaxacceptage`, `strictdate yes` refuses an unreadable Date; the default `strictdate no` retains the old behavior of accepting unreadable dates. Accepted values are yes/no, on/off, and 1/0; other values are configuration errors. With no age limit, no Date is parsed for age. A Date header remains mandatory. This implements the existing `XXX reject the article if parsedate doesn't have a clue?` option.
