- diablo: an `application/octet-stream` part sent without a transfer encoding (none, 7bit, 8bit or binary) is no longer a binary by its header alone: it gets the checks of an unencoded body (uuencode, BinHex and base64 runs) and is a binary once it has 8 bytes that are not text (`B64_ARTTYPE_IS_TEXT` in lib/arttype.c). Pine 3 attached text files that way, and such old text articles were refused as binaries. Sent as base64 or quoted-printable it is a binary as before; the encoding header after the type is now read too, so a base64 octet-stream part also has the base64 type.
- diablo: a quoted-printable text part is a binary only with 8 escapes of bytes that are not text (`B64_ARTTYPE_IS_TEXT`), not at the first one: a `=7F` in a table of characters or a `=1A` (Ctrl-Z) at the end of a DOS file made text articles binaries.
