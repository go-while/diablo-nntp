- diablo: when the host cache is rebuilt (diablo.hosts or dnewsfeeds changed, or after `hostcacherebuildtime`, an hour by default) and the lookup of a peer given by host name gets no answer for now (EAI_AGAIN: resolver down or timed out; EAI_MEMORY; EAI_SYSTEM), the addresses that name had under the same label in the previous cache are kept, each once (and not when an earlier line of the same label and name got fresh addresses in this rebuild), and the general log says so once per label and name in each rebuild (`host cache: <name>: <reason>, N previous address(es) kept`). Before, the name got no record at all, and that peer was refused (`502`) until the next rebuild (by default up to an hour), also after DNS answered again. Other lookup errors (no such name, no address, EAI_FAIL) drop the name as before, and so does removing the peer from the configuration. Kept addresses have no age limit: while the lookups keep failing with those errors they stay, rebuild after rebuild (D-236).
