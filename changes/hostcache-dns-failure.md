- diablo: when the host cache is rebuilt (diablo.hosts or dnewsfeeds changed, or the hourly `hostcacherebuildtime`) and the lookup of a peer given by host name gets no answer for now (EAI_AGAIN: resolver down or timed out; EAI_MEMORY; EAI_SYSTEM), the addresses that name had under the same label in the previous cache are kept, each once, and the general log says so once per name and rebuild (`host cache: <name>: <reason>, N previous address(es) kept`). Before, the name got no record at all, and that peer was refused (`502`) until the next rebuild, up to an hour, although DNS came back a moment later. Every other lookup error (no such name, no address, EAI_FAIL) drops the name as before, and so does removing the peer from the configuration. Kept addresses have no age limit: while the lookups keep failing with those errors they stay, rebuild after rebuild (issue list) (D-236).
