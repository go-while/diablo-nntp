- diablo: with `wireformat on`, a line whose CR is the last octet of a full input-buffer piece (a line of k x the piece size less one octet; 4027 on a 4 KiB page, 64-bit with zlib, with the default `feederbuffersize`) now counts as CRLF-ended, as in text mode: the CR is read again with the LF after it. Before, the "." after such a line was taken as data, so an IHAVE article did not end (the peer got no reply) and over pipelined TAKETHIS the commands that followed were read as part of this article. The stored bytes are unchanged, and the article's size (filters, spool choice, `recbytes`) counts that CR once (D-229).
- diablo: with `wireformat on` and `rejectartswithbarecr on`, a bare CR that is the last octet of a full input-buffer piece is now refused like any other bare CR (437/439), as text mode already did; before, wire mode missed it there and accepted the article.
