- `dreaderd`: a checkgroups control message uses `dcontrol.ctl` the way INN's controlchan uses `control.ctl`. Every checkgroups (and `all`) line that matches the sender is used, not only the last one. They are taken from the last line to the first, and a line acts on the groups that match its pattern and no later line's, so a later line wins. `doit` and `verify-*` lines check their groups, as before. Each `verify-*` line is verified on its own, and one that does not verify is skipped as if it were not there. A `drop` line leaves its groups out of the list, so an earlier `doit` line removes those that exist (INN's `checkgroups:*:*binaries*:drop` example). `log` and `mail` lines change nothing and write their lines of the message to the control log. The change limit takes INN's syntax, `/maxdocheckgroups/:<from>:<newsgroups>:<number>` (`maxcheckgroups:` still works), and each change counts for the last line that matches its group instead of for the first group of the message. A site whose checkgroups lines are all `drop` still never has its groups changed. The tests of the earlier checkgroups change are renamed `TestCheckgroups*` (tests/e2e/checkgroups_docheck_test.go). New tests: `TestCheckgroupsEveryLine`, `TestCheckgroupsLaterLineWins`, `TestCheckgroupsDrop`, `TestCheckgroupsAllDrop`, `TestCheckgroupsVerifySkipped`, `TestCheckgroupsMaxdocheckgroups`.
