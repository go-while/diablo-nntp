- `dreaderd`: a reader-cache file is used only when the article in it has the requested Message-ID. The cache file is named by the hash of the Message-ID alone, and with `msgidhash hash` (the default) and `hash crc` two Message-IDs of the same length that differ only in bit 0 of the 5th byte from the end share a hash about half the time (D-210; `<1510900044@gn>` and `<1510900045@gn>` are such a pair): once one was cached, a request for the other, by Message-ID or by article number, was answered from its file with the wrong article, or with 220/223 although the spool server does not have it. Such a request now goes to the spool server as on a cache miss; the cache file is left as it is. This covers the reader cache only (D-211, its reader-cache half): a Diablo spool server with the same hash also looks the article up by the hash alone, so behind it the other ID can still get the wrong article, now from the spool server (use `msgidhash siphash`, D-210); the overview lookups by Message-ID are not changed here either.
