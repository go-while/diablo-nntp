- `lib/kpdb.c` (active file and other KP databases): `KPDBSort()` stores the offsets through a mapping of the file instead of one `pwrite` per record (D-90; on a full ZFS dataset each write took about 0.2 s while the file was locked). A lookup that misses while a sort is running now waits for the append lock and looks again, so a key is no longer reported missing in the middle of a resort (D-117). `KPDBWrite()` with a NULL token no longer crashes: it unlocks or looks up and never writes or creates, as the comment now says (D-118). A KP file at or past 2 GB is refused with a message instead of wrapping its integer offsets (D-122); the binary search no longer overflows near that size.
