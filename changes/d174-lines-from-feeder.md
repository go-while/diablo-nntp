- The reader's overview `:lines` (the 8th OVER/XOVER/XZVER field, `HDR :lines`, `XHDR Lines`) is now the number of body lines, as RFC 3977 8.4.2 requires, instead of the article's `Lines:` header, which is empty for an article without one and can be wrong (D-174). On a full feed dreaderd counts the lines itself. For a header feed, diablo counts the body lines when the article comes in and writes them to the queue entry as ` L<lines>` (next to ` H` and ` C<size>`; dnewslink's requeue and refile writes and drequeue keep it), and `dnewslink -H` sends them with the size as `Bytes: <size> <lines>` without reading the bodies. dreaderd keeps the count in the overview record's spare field (the file format is unchanged) and does not store the Bytes: line as a header, so clients never see it. Records written before, queue entries without ` L` (an older diablo) and header feeds from an older dnewslink (`Bytes: <size>` alone) keep the `Lines:` header. An older dnewslink ignores ` L`, and an older dreaderd reads the size alone from the new Bytes: line.
- `dnewslink -L` (`genlines`) uses the queue entry's line count; for an entry without one it counts the body as before, but no longer includes the final "." line of an article stored in wire format.
- `dspoolrefeed` writes the body line count (` L<lines>`) into its queue lines as diablo does, so a refeed to a reader through `dnewslink -H` carries `:lines` too; it now reads each article whole to count them.
- `XHDR Lines` and `HDR Lines` give the same body line count as `:lines`, as the overview's Lines field does in INN, instead of the article's `Lines:` header.
