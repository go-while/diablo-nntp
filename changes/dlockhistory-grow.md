- `dlockhistory -a` keeps a growing history file locked. Before, every size change (each article the feeder adds) unlocked and relocked the whole file on every check, every 5 seconds by default. Now a grown file is locked before the old lock is dropped, and only after 1/64 growth. A replaced file is locked anew. An mlock failure is reported instead of ignored: at start dlockhistory exits (so a service manager shows it), and later a failed relock keeps the current lock and is tried again after the next sleep.
