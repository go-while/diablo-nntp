- drequeue: a run that spans a `dspoolout` rotation lost the queue lines written after it: it kept writing to the queue file it opened at start, which `dspoolout` had renamed and `dnewslink` then removed, and still exited 0. drequeue now opens `dqueue/<label>` again by name before a write when the name points at another file or at none. If the queue file cannot be opened (at start or after a rotation), drequeue says so on stderr and in the log once per failure series (again only after the file could be opened in between), keeps the lines in its buffer and tries again on the next write instead of writing to a file it found renamed or removed. Lines that could not be queued (no room left in the buffer meanwhile, still unwritten at the end, or a failed write) are reported at the end ("drequeue: <label>: N lines were not queued") and drequeue exits 1; before, they were dropped without a word and the exit status was 0 (D-238).
