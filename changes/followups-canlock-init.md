- `diablo-ctl`: the paths are derived again when an auto-loaded `<path_home>/diablo-ctl.conf` names other binaries (D-139); an unknown `DIABLO_DAEMONS` entry and a non-numeric `DIABLO_START_WAIT`, `DIABLO_STOP_WAIT`, `DIABLO_ACTIVE_MAXAGE` or `DIABLO_MAX_DOWNTIME` are refused up front (D-140, D-141); a `*` in `DIABLO_OPTS` or `DREADERD_OPTS` is no longer expanded to file names (D-146). The docs of the checks before a start are corrected (a standard install has an empty active file; each daemon is checked and started on its own; `-F start dreaderd`); the systemd units set `LimitCORE=0`.
- `dcanlock`: with `-S`, an explicit `-A` file that cannot be read, or has no such vserverdef, is an error as it is without `-S`; a PATH with an empty last component is the current directory when `dreadart` is looked for next to `dcanlock`.
- CI: `E2E_NO_CANLOCK=1` makes `tests/e2e/ci/build-on-host` build without libcanlock on purpose, so that `TestCancelLockWithoutLibcanlock` can run in a second CI build (the matrix entry in `.github/workflows/e2e.yml` is described in the pull request).
- `readercanlock none` is allowed together with `readerxover trackonly` (it refuses every cancel before it needs a header); `all` and `none` are the two modes that start with trackonly. `build-on-host` installs the Gentoo package `net-libs/canlock` and drops the Arch attempt (no package in the official repositories).
