- `dreaderd`: a checkgroups control message is acted on as INN's `docheckgroups` does with `doit` (an enhancement; D-53 had made it update descriptions only). The descriptions of the groups it lists are updated and the moderated flag of existing groups corrected ("(Moderated)" in the description); the listed groups that do not exist are created (complete records); and the groups that match the `dcontrol.ctl` newsgroups pattern, are in a top-level hierarchy of the message and are not in it are removed. The additions, moderated-flag corrections and removals are only made when there are not more than 10 of them, as in INN; a line `maxcheckgroups:<from>:<newsgroups>:<number>` in `dcontrol.ctl` sets the limit for the sender and first group it matches, the last matching line wins. Beyond the limit they are written to the control log (`doit=logfile`, `mail`) as the `dgrpctl` commands that make them. A file `localgroups` next to `dcontrol.ctl` (a name or wildcard per line) lists groups that checkgroups never changes or removes. The description of a group that the message does not list is never touched. A site that took the real ISC checkgroups (about 1,900 groups) before did not get any new groups; now it needs `maxcheckgroups` raised once to create them, and a narrow third field of the `checkgroups` line or `localgroups` for local groups in the hierarchies of the message. Tests: `TestReaderCheckgroupsControl`, `TestCheckgroupsInn*`, `TestISCControlCheckgroups*`.
