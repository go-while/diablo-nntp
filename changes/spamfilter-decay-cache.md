- diablo: the internal spam filter keeps a tripped slot tripped. A copy whose transfer took longer than 10 s no longer resets the slot (the check uses the time it ends, not the time it began, D-281); a slot that has decayed to 0 starts again from the next copy, so after a quiet time it trips at the trip value instead of letting about one copy per idle minute through (D-282); and a new cache size (`dicmd config internalfilter ... s<n>`, or `dspaminfo` with another size) writes a new `spam.*.cache` and renames it into place instead of truncating the file that feeder processes have mapped, which got them SIGBUS (D-283). Feeder processes started before a size change keep the old cache until they exit.
