- diablo: the internal spam filter keeps a tripped slot tripped. A copy whose transfer took longer than 10 s no longer resets the slot (the check uses the time it ends, not the time it began, D-281); a slot that has decayed to 0 starts again from the next copy, so after a quiet time it trips at the trip value instead of letting about one copy per idle minute through (D-282); and a cache of another size (`dicmd config internalfilter ... s<n>`) is written to a new `spam.*.cache` with the old file's owner and mode and renamed into place, instead of truncating the file that feeder processes have mapped, which got them SIGBUS (D-283; a new, empty cache file is still filled in place); if the owner or mode cannot be kept (e.g. `dspaminfo` run by a user who cannot chown to the cache's owner), the old file is left in place and that process runs without the filter, with an error in the log. Feeder processes started before a size change keep the old cache until they exit. `dspaminfo` uses the size in diablo.config, so after a size set only with `dicmd` it still replaces the cache file with an empty one of that size; running diablo processes now keep theirs.
