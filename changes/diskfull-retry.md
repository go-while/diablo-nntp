- `diablo`: when no spool file can be created (a full disk, an I/O error or no file descriptors left; the "IOError/Missing-dir" reject), the peer is now told to try again later (436 to IHAVE, 431 to TAKETHIS) instead of getting a reject (437/439), so the article is offered again rather than dropped. Seen on a production feeder whose spool filled for 11 minutes during a binary flood: about 1100 articles were rejected and lost. The article is still not put in history.
  - A growing number of these try-again answers ("IOError/Missing-dir" in the incoming log, with "unable to open/create article file ... (reason)" in syslog) means the spool cannot take files: a full disk (ENOSPC), an I/O error (EIO), no file descriptors left (EMFILE/ENFILE), or no usable spool file in the current directory after 10000 tries. A missing parent spool directory is not one of them: the feed process still logs it and exits, as before.
