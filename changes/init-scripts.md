- Init integration: `samples/init/` has a systemd unit, FreeBSD rc.d scripts, an illumos/SmartOS SMF manifest and SysV init scripts for diablo and dreaderd, all thin wrappers around `adm/diablo-ctl`. `diablo-ctl` gets a `check` action and checks before a start (configured mounts, an active file that exists and is not stale, an unclean-shutdown guard, an optional demand for the history file; a missing history is still created by diablo), `-F` to skip them, an optional `dkp` trim and sort of the active file at start (all in `diablo-ctl.conf`), and removes the pid file dreaderd leaves behind after a stop. New adm scripts: `actsync` (sync the active file with an active file server), `dumphist` and `histbackup` (snapshots of a history on a RAM disk).
- Upgrade note: the checks are on by default (`DIABLO_PREFLIGHT=yes`), so `diablo-ctl start` now refuses to start when a configured mount is missing, when the active file that the daemon uses (dreaderd always, diablo only with `active` on in diablo.config) does not exist or is older than `DIABLO_ACTIVE_MAXAGE`, or after an unclean shutdown with a long downtime. A new reader site has no active file yet: create it, or start once with `diablo-ctl -F start`. `DIABLO_PREFLIGHT=no` in `diablo-ctl.conf` turns all checks off. On systems whose `find` has no `-mmin` (illumos) `DIABLO_MAX_DOWNTIME` and `DIABLO_ACTIVE_MAXAGE` are rounded up to whole days.
- The systemd units no longer raise the core file limit (the cores hold the AUTHINFO and Cancel-Lock secrets of dreader.access); the line is there, commented out, for debugging.
