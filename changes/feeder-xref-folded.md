- Feeder Xref slave with `feederxrefsync on`: the whole `Xref:` header is read for the NX sync, also when it is folded over continuation lines or longer than the input buffer (one page with the default `feederbuffersize`), up to the same 16383-byte limit as `Newsgroups:`; an entry cut by that limit is left out. Before, only the first line (and of a long line only its first piece, less its last byte) was read: the groups on the continuation lines got no NX update, an entry cut at the end of a piece set NX to the cut number, and with `activedrop on` an article whose first `Xref:` line named only groups not carried and whose carried groups were on a continuation line was refused NotInActive (recorded in history, so no other peer could deliver it here while the history entry lasted), while one whose `Xref:` named only groups not carried, all on a continuation line, was accepted (an `Xref:` with only the host on its first line was accepted, with no NX update for the groups on the continuation). The stored article is unchanged.
