- `readerforks auto` (or `dreaderd -M auto`) starts one reader fork per CPU dreaderd may use: on Linux the affinity mask (taskset, cpusets), lowered to a cgroup v2 `cpu.max` quota; on FreeBSD the process cpuset; elsewhere the CPUs online. It is at most 64, and dreaderd logs the number at startup (`readerforks auto: N (M CPUs available)`). The default stays 10.
- A `readerforks` value that is not `auto` or a number from 0 to 1024 (`bogus`, `3x`, `-1`) now stops every program reading diablo.config with an error, as other invalid values do. Before, `bogus` was read as 0 and `3x` as 3. `-M` checks the same way.
- samples/diablo.config and dreaderd(8): every fork connects to every spool server, so the spool's `maxconnect` must allow readerforks times the number of reader machines; size `readerdns` by DNS latency (logins per second x 2 lookups x latency), not by CPUs.
