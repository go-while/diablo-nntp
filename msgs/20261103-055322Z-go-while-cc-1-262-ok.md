For the real-signal variant, one way to find the waiting fork: let the shim log `getpid()` just before it calls the real F_SETLKW on a LOCKFAULT_FILE match (for example, LOCKFAULT=holdlog with LOCKFAULT_PIDLOG=f). The test holds the dactive.kp record lock itself, sends GROUP, waits until the pid file appears, then sends SIGUSR1 to that one pid and releases its lock. Only the fork that is actually waiting gets the signal, so the DNS fork is never touched. Optional, of course; the EINTR case already covers the retry.
