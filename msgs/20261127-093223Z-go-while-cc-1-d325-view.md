[Claude] D-325 view, as asked (Jesse decides; this is reading and one search, nothing was run for it).

(a) A reason we missed? I found none. FindGroupDir() skipping components of 0 or 1 characters is in the 2017 import unchanged (4b802321, lib/hash.c: "if (p - q <= 1) { p++; continue; }"), with no comment, no test and nothing in samples/diablo.config, the README files or the man pages that mentions it. The hierarchy layout is documented as "not recommended for large servers" (samples/diablo.config, readergrouphash). I cannot rule out an intent such as avoiding one-letter directories in short-name hierarchies; nobody who wrote it is around to ask. One thing I checked: the skip drops a directory, not a name: the file name is always the full group name, so for every group except the X / X.gz pair the skip changes nothing in uniqueness.

(b) Migration or option: my view is against an in-place migration for this edge. The conflict needs a group X whose last component has one character and a group X.gz; both are rare, and the layout is the niche one. A migration touches the files of every existing group that has a one-character component anywhere (not only as last component: e2e.x.foo moves from e2e/ to e2e/x/), while readers are expected to be off or to miss files for a while, and clean and dexpireover run on the same tree: that is the exact area where this review series found six data-loss paths in two days. An option for new spools (your readergrouphash hierarchy2) moves nothing and leaves old spools as they are, so it is the smaller blast radius; the price is the collision stays in old spools, which D-325 can state plainly. The third way is to keep the layout and make the pair impossible (refuse creating X.gz when X exists with a one-character last component, in newgroup, dgrpctl newgroup and dsyncgroups); you declined it, so I mention it only as the cheapest in files touched.

If you still choose the migration: it needs a dry-run mode that lists every move, a lock order (record lock, then the rename of the over file and each data file, then ITER and the header untouched), a crash-safe order (copy or link before unlink, so a kill in the middle leaves both paths and the next run finishes it), a test that kills it at random points, and doverctl clean and dexpireover must refuse to run while a relayout marker exists.

D-326 (CleanSpool entering only directories whose name starts with two alphanumerics, util/doverctl.c ~:615) is independent of the layout decision and cheap; with the option route it is still needed, because a user can already have one-character top-level directories today. I would do D-326 alone first.
