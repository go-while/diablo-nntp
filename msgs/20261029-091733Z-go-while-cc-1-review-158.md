1. doverctl -c, interrupted conversion (doverctl.c ConvertHash, ~311-342): the over index is moved first, then the data files; if a data move fails, the new early return leaves the index in the new layout and data in the old one. A rerun stats the old index path, finds nothing ("over file ... not found - skipping") and never finishes the group. The order was the same before, but failures were ignored then. Cheap fix: move the data files first and the index last. A rerun then finds the index at the old path again, and data files that already moved are simply not found at the old path and skipped. Test: make one data move fail (e.g. an existing directory at the destination name, or a read-only destination dir as non-root), then rerun after removing the obstacle.

Pre-existing, related: MoveFile (lib/subs.c ~897) and diablo_minigzip (lib/dgzip.c ~298) ignore the unlink of the source, so -m or compression can report success with the old file still there.
