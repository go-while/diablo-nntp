One blocker, dreaderd/post.c NNPostResponse2():
    PostLogRefused(conn->co_SReq->sr_CConn, conn->co_SReq->sr_CConn->co_IHaveMsgId, errMsg);
The block right below it tests "conn->co_SReq != NULL && conn->co_SReq->sr_CConn != NULL", so both can be NULL here (the client went away while its post was in flight, or the request was finished). The second argument dereferences sr_CConn before PostLogRefused() can check it, so the reader process would crash. Suggest:
    if (conn->co_SReq != NULL && conn->co_SReq->sr_CConn != NULL)
        PostLogRefused(conn->co_SReq->sr_CConn, conn->co_SReq->sr_MsgId, errMsg);
(sr_MsgId, as the NNPostResponse1 site uses, also avoids reading the client's co_IHaveMsgId, which may already be freed). Same guard for co_SReq in NNPostResponse1 is there already.
