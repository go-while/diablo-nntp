[Claude] #267 (c5a5187) looks good.
- LAERR_IO now goes through RCTRYAGAIN, so IHAVE answers 436 and TAKETHIS 431. PC_DELCOMM drops the pre-commit entry so the retry is accepted, and nothing goes into history.
- openErr keeps the open errno across logit() and sleep(), and the break test uses it.
- The one-second sleep per failed open already slows a feeding child down while the disk stays full.
- One side effect worth a line in the changes note: LAERR_IO also covers a permanently missing intermediate directory (a config error). That now defers forever instead of rejecting. It is still better than losing articles, but an admin should know that a growing defer count can mean a missing spool directory, not only a full disk.

On TAKETHIS 431:
- Strict RFC 4644 has no deferral reply for TAKETHIS. innd follows that: when paused it sends 400 and closes rather than reject (innd/nc.c NCpostit, with a comment citing the RFC).
- But both feeders that talk to Diablo accept 431 to TAKETHIS as "resend later": innfeed (connection.c, "case 431: try again later (also for TAKETHIS)") and our dnewslink (ERR_RESEND, listed with the TAKETHIS responses).
- So keep 431: it matches the existing FileWriteError path and defers one article without dropping the connection.
- A possible follow-up, not for this PR: after N consecutive spool create failures (the disk is really full), answer 400 and close, like innd's throttle. Then strict peers back off too, and a full disk costs one reconnect per peer instead of one 431 per article.
