1. NNFeedOverview(): newsgroups comes from zallocStrTrim2() (zalloc of strlen+1) and is freed with zfreeStr(), which frees strlen(*ps)+1 (lib/zalloc.c:306). NormalizeNewsgroups() can shorten the string in place: "a,b," / ",a,b" / "a,,b" / "a ,b" / "a  b" all lose bytes (a single space -> comma keeps the length). Then zfree() gets a smaller size; it rounds to 16 bytes (MEMNODE_SIZE_MASK), so when the shrink crosses a 16-byte step the tail stays allocated and mp_Used stays high until the connection's pool is freed. The feed connection from diablo lives for days, so it is a slow leak per such article (a trailing comma is common in binary posts; TestNewsgroupsEmptyEntry has it). Both free sites are affected (:320 the control rewrite, :446 the end).
   Suggestion: keep the alloc size and swap in an exact copy, so the zfreeStr() calls stay right:
       newsgroups = zallocStrTrim2(...);
       { int n = strlen(newsgroups) + 1; char *t;
         NormalizeNewsgroups(newsgroups);
         t = zallocStr(&conn->co_MemPool, newsgroups);
         zfree(&conn->co_MemPool, newsgroups, n);
         newsgroups = t; }
   (A DEBUG_ZALLOC build should flag the current mismatch in dbg_zalloc_free, if you want a check.)
