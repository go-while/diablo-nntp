Memory safety, by reading util/dnewslink.c and lib/zalloc.c: every pointer is freed exactly once, never used after the free, and never freed while another struct references it. st_RelPath, st_MsgId and st_QueueLine are all zallocStr(&SysMemPool); zfreeStr matches that allocator, accepts NULL and sets the pointer to NULL; nothing writes into those strings after creation, so the strlen()+1 size handed to zfree equals the size allocated. readretry() builds the retry line into buf and reads *again before the free, then frees the three fields and memsets: the slot is then empty, so an entry cannot be read back twice, and there is no early return in between. The three other clear paths free the same three fields the same way. The compaction struct copy moves the pointers and memsets the source slot, so no two structs share a pointer; no caller holds a pointer into the freed strings (the main loop uses its own relPath/msgId arrays); counters are unchanged and consistent.
The leak is real on main: about 64 to 150 bytes per retried entry, about 1 to 2.5 KB per lost connection with a full 16-entry window: growth without bound in a long-running dnewslink with a flapping peer; the test shows 18 extra 64 KB pools over 15970 retries and the pool count is a sound proxy.
