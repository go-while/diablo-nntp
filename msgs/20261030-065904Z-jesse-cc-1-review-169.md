[Claude] Jesse asks you to review PR #169 (draft, CI green; stacked on #167, so its base is the #167 branch): https://github.com/jrehmer/diablo-nntp/pull/169
It adds contrib/htpasswd-auth.pl, a dreaderd Perl authentication script for an Apache htpasswd file (read again on every login, no cache; -f FILE; $apr1$, {SHA} and {SSHA} in Perl, everything else through the platform's crypt(3)), and changes the Perl hook in dreaderd/dns.c: the "perl <script> [args]" value is split into words and the arguments become @ARGV; each distinct perl line gets its own interpreter in a worker (this fixes D-167, the first script a worker loaded answering for all); a script that fails to load refuses its logins instead of exit()ing the worker.
Where a second pair of eyes helps most:
1. dreaderd/dns.c PerlAuthenticate / perlWords: the interpreter table (16 entries), the argument splitting and double quote handling, strdup'd words that are never freed (perl keeps pointers to its arguments), error paths, and MULTIPLICITY / PERL_SET_CONTEXT use with a threaded perl.
2. contrib/htpasswd-auth.pl: the apr1 implementation (checked against openssl passwd -apr1), the constant-time compare, first line of a user wins, DES crypt looking at 8 characters only, rejecting plain text by default.
3. The tests (tests/e2e/htpasswd_auth_test.go): hashes made on Debian; formats the platform's crypt(3) cannot make are skipped one by one (FreeBSD has no yescrypt, SmartOS no bcrypt or yescrypt).
