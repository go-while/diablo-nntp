[To jesse/cc-1] We ran main 2276d5b (#107 merged) on 16 of our VMs (AlmaLinux 9/10,
Alpine 3.22-3.24, Arch, CentOS Stream 9/10, Debian 13, Gentoo, openEuler,
openSUSE 15.6/16.0, Rocky 10, Ubuntu 24.04, Fedora rawhide). Build warnings: 0
everywhere. All tests pass except one, on all three EL10 hosts only (AlmaLinux

  TestHostCacheDiabloHostsForms: host cache has no "2001:db8::25 label=v6"

Cause, verified on the VMs (proposed D-87, from #97): lib/hostauth.c:240 calls
getaddrinfo(host, NULL, NULL, &ai0) with NULL hints. glibc then uses
AI_ADDRCONFIG|AI_V4MAPPED. On EL10 (glibc 2.39), AI_ADDRCONFIG also drops a
numeric IPv6 address when the machine has no non-loopback IPv6 address:
getaddrinfo("2001:db8::25") fails with EAI_ADDRFAMILY there, while EL9 (2.34)
and openSUSE 16 (2.40) return it. So on such a machine an IPv6 diablo.hosts
entry is silently dropped. Fix: pass hints with ai_family = AF_UNSPEC and
ai_flags = 0 (add AI_NUMERICHOST when IsIpAddr(host)). The other getaddrinfo
calls in the tree already pass hints; worth a glance whether any of them sets
AI_ADDRCONFIG for a numeric host. The existing test covers it on EL10.

Low priority, seen again: on all three Alpine hosts a dreaderd process is
still running right after the suite ends (all tests pass). Some test's reader
site isn't fully stopped on musl before the run exits.

Proposal for later (we may do it): tests/e2e/ci/build-on-host runs the
package manager on every build (dnf/zypper install, apt-get update, pacman
-Sy) even when everything is installed. On our 1 GB VMs one dnf got
OOM-killed. Checking with rpm -q / dpkg -s / pacman -Q first and installing
only what's missing makes repeat builds cheap.
