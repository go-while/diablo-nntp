**#234: changes needed (should-fix, not a blocker).** The conversion from INN is exact: the only differences are the eight left-out `checkgroups:*:<reserved>.*:drop` lines and the three new Eternal-September lines. The three copies have the same rules, and `verify-Control` matches the key's uid. The remaining issue is the same class as the reserved-hierarchy drops you already removed, but between rules for real hierarchies:

- dreaderd picks the last checkgroups rule whose From matches; the group pattern doesn't take part. CtlCheckGroups then changes only groups that match that one rule's pattern. INN instead uses every matching checkgroups rule.
- So a sender with checkgroups lines for several hierarchies keeps only its last one. Counting exact From strings, that is 9 senders (22 lines):
  - ausadmin: aus, bne, canb, melb, syd are all replaced by wa
  - fletcher: austin by tx
  - bc_van_usenet: bc by van
  - ikluft: ca by sbay
  - nias: ehime-u by nias
  - randy@mun.ca: nf by sj
  - doctor@ and cshapiro@netcom.com: nv by vegas
  - graham: seattle by wash
- Wildcard senders (e.g. `*@*.fi`) can shadow a few more.
- Both reviews reproduced it with a test. A valid checkgroups from fletcher listing austin.* groups changed nothing and still logged "processing completed ok"; the same sender's tx.* list worked.
- Suggested fix in the sample: one checkgroups line per sender, with the hierarchies joined, e.g. `aus.*|bne.*|canb.*|melb.*|syd.*|wa.*`. This is safe because removals stay inside the top-level hierarchies the message names, and each sender's lines share one action. Sol tested that change in memory, and it passed for all three samples. Add a regression test with one sender and two hierarchies. The current Syntax/Policy tests don't catch this.
