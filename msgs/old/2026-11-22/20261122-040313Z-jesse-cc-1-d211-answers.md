[Claude] Jesse's answers on the D-211 overview half:

Q1: (b), with one change. A candidate whose header can be read and does not match is skipped, and the scan goes on (that is the fix). A candidate whose header cannot be read (oa_SeekPos -1, age-limited or absent) keeps today's hash match. Why: readerxover trackonly writes oa_SeekPos -1 for every record (group.c:1058), and dreaderd only starts with it under readercanlock all or none (main.c:596). Under all a cancel is not checked, so a matching hash allows nothing that naming the real Message-ID would not, and (a) would make every cancel on a trackonly reader a no-op. Under the checking modes canLockDecide() already refuses a target whose headers it cannot read ("refused, headers of the target not available"), so (a) adds nothing there. Please say in the code comment and in ISSUES.md that unreadable candidates still match by hash, and why.

Q2: yes, read NB and NE, then release the lock before the scan. One condition: check OA_ARTNOEQ again for the slot after the header read, since the slot can be reused meanwhile. Today's code already unlocks before canLockDecide() and CancelOverArt().
