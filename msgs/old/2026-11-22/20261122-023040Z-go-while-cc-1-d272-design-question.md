[Claude] D-272 (DirTime is one global value for all metaspools) is bigger than the entry says, and has behaviour questions that are yours. Your answer 20 said: take the value from the spool object's own setting (so_DirTime). A first version did that (distinct spool objects work), but four reviews found: (1) spool objects may be shared by several metaspools (samples/dspool.ctl:98-101), so the last metaspool allocated overwrites the value in the shared object and the other metaspool's articles still go to the wrong directory. A correct fix keeps the time with the metaspool's allocation (a field next to ms_AllocatedSpool in lib/defs.h; findSpoolGrp()/GetSpool() hand the matched time back; both feeder lookups in util/diablo.c use it; util/dfeedtest.c passes NULL): files lib/defs.h, lib/spool.c, util/diablo.c, util/dfeedtest.c. OK to do it that way?
(2) Expiry: cleanupDirectories() (util/dexpire.c ~:764-795) protects the highest-named slot, not the slot in use. With a 1h metaspool listed before a 10m one, main can leave a 12:40 directory on the hourly spool; after the fix new hourly articles go to 12:00, which dexpire may remove under space pressure while the feeder still appends (its removal path takes no append lock). Options: (a) leave it and document the mixed-interval setup as one to avoid, (b) protect directories in use (tracking = new behaviour, a separate change). Which?
(3) Age: History.gmt serves as both the location of the file and the article's age (ARTICLE <id> a<N>, dhisexpire -T, age-limited dspoolrefeed). Recording the metaspool's slot instead of the global one makes a new hourly article look up to one interval older (40 minutes at 12:40; an a1800 request can answer 430). Accept and document, or keep a separate age value?
(4) A computed slot of 0 (reallocint 22000d rounds to 0): HistoryAdd logs gmt=0 and returns success without storing the record, so the article is accepted (235) but cannot be found by Message-ID. Refuse that reallocint at load (new refusal, opt-in?), treat it as an error at the feeder write, or leave?
Our default if you do not mind: (1) yes, (2) a, (3) accept and document, (4) error at the feeder write only (not at load). Tell us if different.
