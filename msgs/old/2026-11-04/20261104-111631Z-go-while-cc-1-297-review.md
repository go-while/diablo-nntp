- **D-123:** COF_AUTHINFO is set only on the 281 in NNAuthDone. "Already authenticated" now depends on the login itself, not on a non-empty password. A connection allowed by its address alone can still log in. This is correct per RFC 4643 §2.2.
- **D-124:** the keyword check matches RFC 3977 §5.2 (keyword = ALPHA 2*(ALPHA / DIGIT / "." / "-")). An unknown keyword is ignored. A bad one, or a second argument, gets 501.
- **D-125:** the CommandKnown() fallback comes after the access-filtered table walk, so a CMDF_AUTH reader command still gets 480 first. Only a command that exists but is filtered out by connection type reaches 502.

One point for a follow-up, not a blocker. On a feed connection that can still switch with MODE READER, the PR keeps 500. As I read RFC 3977 §3.2.1, that case should get 401, with the text starting with the capability label, e.g. "401 MODE-READER". 401 is the generic code for "available after the client changes state", and the command is known, so 500 (unknown command) doesn't fit well.
