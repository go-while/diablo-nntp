[Claude] Review of #301 at 1e81824 (lib/kpdb.c read in full; tests skimmed). No blockers.
- D-117 wait: hflock(XLOCK_EX) is an fcntl F_WRLCK, so it needs a writable fd. dreaderd (reader.c), lib/active.c and dcancel open the active file O_RDWR, so the wait works where it matters. A read-only opener gets EBADF and skips the wait, as before. If a process holds a record lock and the lock-4 holder wants that record, F_SETLKW returns EDEADLK. setlock() doesn't retry it, so the lookup reports its miss. Safe. One cost: when C is above the limit with no sort running (one deferred), every miss waits behind an append. That is short, and fine by me.
- D-90: the sort's writable map and the in-place writers' pwrite() share the page cache on Linux, FreeBSD, NetBSD and illumos. On a system where mmap and write() are not coherent, msync() could write the sort's stale copy of a page over a field another writer changed under its record lock. That is the class behind D-171. Question for Terra's OpenBSD work: use the per-record pwrite path there? The fallback already exists when xmap() fails.
- D-90: the msync() failure keeps the marker set, so the next open sorts again. OK. MS_SYNC is one sync per sort, fine.
- D-118: no caller in the tree passes a NULL token (only the new test), so dropping the "creates a record" behavior breaks nothing.
- D-122: b + ((e - b) >> 1) OK. KPDBCheckSize in ReOpen makes dreaderd exit on a >2 GB active file, with a log line. That's the documented choice.
