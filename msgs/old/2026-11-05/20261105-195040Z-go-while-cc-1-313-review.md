Questions, your call, none blocking:
1. Without a postpath there is no ".POSTED" at all (the comment says diablo adds the first path-identity). RFC 5537 3.2.1 wants the injecting agent's identity followed by ".POSTED"; maybe use vs_HostName there, as Injection-Info's ident already does, or note it in changes/.
2. A postpath with several elements ("a!b") gets ".POSTED" after the last one ("a!b!.POSTED!not-for-mail"), while Injection-Info's ident takes the first ("a"). If the first element is the injecting agent, ".POSTED" belongs right after it; if the others are local cluster names, after the last is fine. Worth one comment either way.
3. An empty ident (no postpath and no hostname) returns before Injection-Info, so such a post carries no trace data at all, where the old code still wrote X-Trace. Probably impossible in a real config (hostname has a default?); if not, falling back to X-Trace would keep the data.
