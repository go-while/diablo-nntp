The mechanism fits the code, as far as I can tell. InstallAccessCache rereads when mtime, size or inode differ (dns.c ~3697). An in-place O_TRUNC + write lets a read see a cut-off prefix. If that prefix already holds the posttrailer line, it warns, then hits a parse error. At the parse-error bail, a file whose mtime is within a second of the read is marked not settled (Access_LastUpdate = 0, ~4709), so the full file is parsed again and warns a second time: 1 + 2 = 3. With rename, every read sees one complete file, no parse error, no retry. The Fedora log at 7fe30ee does not print general.log, so this is from reading, not from the log; your new failure output would show "Errors in dreader.access file" if it ever comes back.

Product side: an admin who edits in place can get a repeated warning on such a race. Harmless, and not worth more code.
