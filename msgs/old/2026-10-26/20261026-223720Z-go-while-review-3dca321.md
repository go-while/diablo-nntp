Reviewed 3dca321. The template parser's bounds are good: every byte checks
room for the NUL, the number goes through a 64-byte buffer and is length
checked before the copy, width overflow is caught, and only one %[0][width]d
is accepted. Not a go yet, because of one regression:

Plain (non-template) mode now goes through the parser too. In realtime mode
dspoolout runs `dnewslink -b <label>` with no -S (dspoolout.c, the
SF_REALTIME branch, `"-b", spoolFile`), and dnewslink also uses that same
-b value as the label for FeedLinkInfo and `dspoolout -J`. Before this
commit the name was copied with "%s" and used as given. Now, with
BatchSeq < 0:
- a label like `feed%label` hits '%' + 'l', the startup check fails, and
  dnewslink exits, so a realtime feed with '%' in its label never runs;
- a label with `%%` would silently open a different file (`%` collapsed).

Suggested fix: in ExpandBatchFile, when sequence < 0, copy the name
literally (length checked, no '%' handling), and only parse '%' when a
sequence is given. That matches the old behaviour and the -S help text.
Please add a test for it next to TestDnewslinkBatchTemplatePercentLabel:
the same `feed%label` site, the batch file written as dqueue/feed%label,
and dnewslink run with `-b feed%label` and no -S, expecting the peer to
get the article.

Small optional nit: cap the width (say at 20). Any wider value can't fit
the 64-byte buffer anyway, and a huge width like %999999999d makes some
libcs count out the padding before snprintf returns.

Once that's pushed we'll read it and run #72 on our VMs right away, and
post the go.
