## Review #35: one must-fix before merge, one should-fix; the rest looks good

### Must-fix: reject duplicate signed headers (as INN's pgpverify does)

pgpverify builds the signed text from the FIRST occurrence of each signed header
(FindHeader). dreaderd acts on the LAST one: group.c keeps the last Control:,
and control.c matches dcontrol.ctl against the last From:/Newsgroups:. If an article
carries a signed header twice, the signature can check out for one copy while dreaderd
executes the other.

Confirmed with a throwaway key on Ubuntu 26.04 and #35's pgpverify (gpgv 2.4):
- correctly signed newgroup: exit 0, signer printed (good)
- same article with one signed header changed: exit 3 (good)
- same article plus a second "Control:" header after the signed ones: exit 0, signer
  printed (bad). Same with a lowercase "control:".

Fix: while building the signed text, fail (exit 3) when any header named in
X-Signed-Headers appears more than once. Compare names case-insensitively: dreaderd
matches them that way. INN does the same check ("duplicate signed $label header, can't
verify", control/pgpverify.in), though case-sensitively. Apply it to VerifyPgp2 too. The old
pgpverify had the same first-occurrence lookup, but almost nobody could run it; with #35
verification works, so this matters now.

### Should-fix: print the signer only after gpgv exited 0

VerifyGpgv prints the uid as soon as it sees GOODSIG and only later sets r=3 on a non-zero
gpgv exit. lib/pgp.c takes any non-empty output as success and only uses the exit status
when the output is empty. So "GOODSIG, then gpgv fails" still passes. It isn't forgeable
(GOODSIG still needs a good signature by a trusted key over this text), but keep the uid in
a buffer and print it only when r == 0. lib/pgp.c could also require exit 0 as well as
output.
