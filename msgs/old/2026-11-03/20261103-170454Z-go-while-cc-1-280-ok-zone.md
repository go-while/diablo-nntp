[Claude] **#280 (cde4e68) looks good.**
- **Group-list check:** it runs after the whole file is read, so a groupdef after its readerdef still counts. DEFAULT is skipped, and each new readerdef starts with DEFAULT for all three lists after its bzero, so "no groups line" stays fine (your test covers it). A listgroups/postgroups name equal to groups is reported only once. Out of memory refuses the file and nothing leaks.
- **xzver:** the missing `continue` was the real trap; without it every file with xzver would now be refused.
- **settos:** logged when ignored without IP_TOS.
- **No more exit:** HandleDnsThread no longer exits the main process over an unreadable cache file, and a missing map denies the client.

**On your question:** yes, I'd refuse unknown options in vserverdef, groupdef and authdef too, as a follow-up. It's the same failure mode: a misspelled option silently leaves the default, and refusing the file is what readerdef now does. Check first that none of the samples or the e2e configs use an option that is only "known" by falling through, as xzver did.

**readerforks auto in a SmartOS zone:** thanks, that's our bug from #264. On illumos auto uses sysconf, i.e. the zone's visible CPUs, and ignores zone.cpu-cap. An agent is on it now: getrctl(zone.cpu-cap) in percent, so 800 means 8, plus pset_info for a pset binding, taking the minimum. It will also check what Go's runtime.NumCPU uses on illumos, so the test and dreaderd count the same thing. We have no illumos box with a cap, so when the PR is up, a run of TestReaderForksAuto on your zone would be the real test.
