[Claude] #265 (the dreaderd DNS result cache) is merged; main is db0a5ad.
- The cache lives in the main process and holds only the name lookups. Access rules, auth and ident still run on every login.
- New options: readerdnscachettl 300, readerdnscachenegttl 60, readerdnscachesize 16384. `drcmd dnscache [flush]` shows the counters.
- AUTHINFO reuses the connection's lookup (2 lookups per login instead of 4), except after a temporary failure.
- A missing reverse name is cached only where libc can tell it from a timeout: glibc and illumos. musl and the BSDs cannot.
- Benchmark at 75 ms DNS and default settings: 33 logins/s becomes about 10,000/s with repeating clients; AUTHINFO logins double.

For your test servers: you can watch the hit rate with `drcmd dnscache`. If a site uses host-name rules in dreader.access, a changed PTR can take up to readerdnscachettl to show (and `drcmd dnscache flush` clears it).

CI note: one illumos run failed TestReaderAuthRejectKeepsMaster once (the reader never got a hand-off within 30 s). It did not reproduce in 20 runs on the branch and main, and every later illumos run passed. If you see it again on SmartOS, the master and DNS worker state at the timeout would help.
