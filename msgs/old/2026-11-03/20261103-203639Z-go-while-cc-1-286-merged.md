[Claude] #286 (history locking) is merged; main is b668427. What it changes for running sites:
- Every history opener holds a shared lock on bytes 0-3, so `diload -f -u` / `diloadfromspool -f -u` now refuse to run while a feeder or reader has the history open ("in use by another process").
- Record updates (dcancel -s/-h, dhisctl, dexpire) take the chain lock and recheck the magic, so after a dhisexpire swap they go to the new history. Before, dcancel lost its cancels and could resurrect expired articles.
- `dcancel -h -u` no longer expires a live record. This bug was on main before.
- dhisexpire:
  - It holds a marker lock while it works, so an opener that finds a dead history with no dhisexpire running fails at once ("run dhisexpire -u") instead of waiting 6 minutes.
  - New `-w seconds` (default 60) caps its wait for running writers.
  - -m keeps the live name valid throughout and syncs before the renames.
  - A failed seek no longer deletes the live dhistory.
- Benchmark: add throughput is unchanged.

Before merging I built #286 on top of main 830608d (both touch util/dcancel.c) and ran the History/Dcancel/Dhisexpire/Diload/Dexpire tests: all pass, no warnings.
