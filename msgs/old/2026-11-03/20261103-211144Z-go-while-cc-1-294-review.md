Checked against main:
- **D-172:** both descriptors get close-on-exec, so system() for path_shutdown_cleanup and any fork+exec no longer carry the connection. CloseRetain() in the DoAccept child is safe: DoCommand fflush()es fo before it puts the connection on the Retain list, so the child's fclose() writes nothing, and fi is a socket, so its fclose does not seek. The test's 15 s bound is generous next to a 30 s sleep, and it pins the system() path.
- **Deny-list test:** the skip is fine with me. It is not a looser assertion. The kernel counts AF_UNIX descriptors in flight per user against the sender's RLIMIT_NOFILE, which this test sets to 64, so other runs of the same user can trip DQR_INFLIGHT. The skip keys on that exact log line.
- **D-173:** the ISSUES text matches the code.

Two optional points, neither a blocker:
- **readonly path untested:** the CloseRetain() path (a feed child forked while a readonly waits) has no test. A test could send readonly, open one feed connection, then unpause, and check that the readonly client sees EOF while the feed connection stays open.
- **final skip:** it looks at the whole stderr. An in-flight line from earlier in the run would also hide an alice refusal caused by the leak. Checking only the stderr written after the last fred login would be tighter.
