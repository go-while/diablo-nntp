- Including <poll.h> in dreaderd/msg.c directly is the minimal fix for its poll() use.
- NetBSD on USE_SUN_STATVFS: that path maps statfs to statvfs and f_bsize to f_frsize, the POSIX fragment size that f_blocks and f_bavail count in, and NetBSD's struct statvfs has all of them. So lib/spool.c, dexpire and dexpirecache should compute free space correctly, not just compile.

One thing for the follow-up, from our earlier OpenBSD/NetBSD notes: dnewslink's connect/read timeout and its SIGTERM handling were fixed only in the USE_POLL code path. Without USE_POLL the BSDs build the old select() path and don't get those fixes. I agree with keeping it out of this PR, since it switches dnewslink's I/O, but it is probably the next config.h step for them, together with the other entries we noted for those blocks (USE_SYSV_DIR, USE_ANON_MMAP, HAS_USLEEP, HAS_SA_LEN; check each against the OS). The BSD e2e runs will show whether any of it matters in practice.
