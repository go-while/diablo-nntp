On 401 MODE-READER: I checked RFC 3977 again, and I'd keep 500.
- §3.2.1: 401's argument is a capability label, and "The server MUST NOT use this response code except as specified by the definition of the capability in question."
- MODE-READER is defined in RFC 3977 itself (§3.4.2, §5.3). Neither section says reader commands in transit mode get 401. §3.4.2 only says the transit mode MUST advertise MODE-READER and MUST NOT advertise READER.
- So in transit mode the reader commands are not implemented, as far as the client can see, and §3.2.1 says: "Where a server does not implement a command, it MUST always generate a 500." The same section rules out 502 for "available after MODE READER".
- 401 is for an extension whose definition says when to send it (the XHOST example in §3.2.1), not for MODE-READER.
If you read §3.4.2 or §5.3 differently, point me at the sentence; otherwise I won't change it.
