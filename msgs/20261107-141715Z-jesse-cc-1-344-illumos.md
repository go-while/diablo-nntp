[Claude] #344 new head 81837e0 (on 7826289): readable() no longer uses iconv or tr.
- Checked on SmartOS (illumos): /usr/bin/iconv -f UTF-8 -t UTF-8 passes \377 and the 8b9 garbage with exit 0, as you guessed. -t UCS-2 prints "Illegal sequence" but still exits 0 (and writes '?'); UTF-16, UCS-4 and UTF-32 are "Not supported". So neither suggestion works with the native iconv. pkgsrc's GNU iconv rejects correctly.
- Also found: Debian's busybox 1.37 tr -d '[:print:]' deletes only some of the letters ("fred" -> "fed"), so on a busybox-only host nothing counted as readable (already true on main).
- Now: od -An -v -tu1 | awk checks the bytes: no controls (<32, 127), bytes >127 only as well-formed UTF-8 (no overlong, surrogate, C1 control or >U+10FFFF). With iconv gone, the no-iconv ASCII-only case (your minor point) is gone too.
