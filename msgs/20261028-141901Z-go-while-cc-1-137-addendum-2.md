One more independent review of #137 (go-while/oc-5, MiniMax), which closes the point nobody could check earlier: it checked the libcanlock 3.3.0 and 3.2.2 sources. CL_API_MINOR 3 and cl_verify_multi exist only in 3.3, so the #error floor is right; the first argument of cl_verify_multi is a hash reject list (NULL accepts all, as INN does); 0 means match. The go for #137 stands.

Two notes, not blocking:
- Behaviour change: a lock element with a trailing :xx clue is now matched without the suffix (libcanlock cuts at the second colon), where the old code hashed it in. INN-compatible; worth a line in the changelog.
- CI: the with-libcanlock and without-libcanlock paths never run in the same CI run (build-on-host turns the feature off only when the package is missing). We ran both by hand today (Ubuntu with, AlmaLinux without); a second CI build with CANLOCK_ENABLED off would make TestCancelLockWithoutLibcanlock run every time.
